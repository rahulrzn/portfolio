# Rahul Reji R. portfolio

React, TypeScript, Vite, Tailwind CSS and Motion, deployed through Cloudflare Pages. The public portfolio and authenticated admin share content through Pages Functions and Cloudflare D1. Content updates do not require rebuilding the website.

## Run locally

Use Node.js 22.12 or newer. No Android SDK or Docker is required.

```powershell
npm.cmd ci
npm.cmd run admin:password
npm.cmd run dev
```

Enter and confirm your owner password privately in the interactive terminal. The tool writes ignored server configuration and never prints the password or hash. Restart development after changing it.

Open the printed `http://127.0.0.1:5173` address. `/admin` uses the password you chose. Local development applies only additive local migrations and uses a separate D1 database; use the online admin to update production.

Public routes: `/`, `/about`, `/skills`, `/projects`, `/projects/:slug`, `/research`, `/contact`. Admin sections: Overview, Profile, About, Projects, Skills, Research, Social links, Contact and Settings.

## Manage content

Edit a section and **Save draft**. **Preview** renders the saved draft with the public components. **Publish → Publish now** atomically makes the saved draft public for every visitor of that environment. Refreshing the admin restores saved content and the server session.

The admin manages profile and portrait, biography and education, projects and GitHub/live URLs, skills, research, social profiles, contact details, opportunities, resume references, SEO and footer settings. Social links support GitHub, LinkedIn, Instagram and X, with URL validation, visibility and ordering. Enabled links appear in the hero, contact page and footer.

Public content revalidates on page load, focus, tab visibility and every 30 seconds while visible. APIs use ETags; Functions generate current public HTML metadata and sitemap entries from published D1 content, including new project slugs.

Settings exports portable JSON backups with referenced images. Imports stage a draft and preserve published content until you publish. Revert restores the published draft; Restore defaults stages original content. Earlier localStorage/IndexedDB content is supported through explicit legacy import or portable backup migration. Export older browser edits from their original browser and origin before migration.

Saves check revisions: a stale editor receives a conflict instead of overwriting a newer version. Failed saves preserve form text. Server sessions expire after eight hours and can be renewed without discarding unsaved text.

## Deploy and connect Cloudflare

Follow [the deployment guide](docs/cloudflare-deployment.md) for the D1 binding, additive migration, password secret, production/preview configuration and full-source deployment steps.

Production admin: **https://rahul-portfolio-j94.pages.dev/admin**. Setup requires:

1. A production D1 database bound as `PORTFOLIO_DB`, with its real ID in `wrangler.jsonc`.
2. The additive database migration.
3. A server-only `ADMIN_PASSWORD_HASH` secret generated by `npm run admin:password`.
4. A Pages deployment containing the built frontend and the root `functions/` source.

Use the existing Git integration or run Wrangler from this repository root. Uploading only a `dist` ZIP through the dashboard does not deploy the source Functions directory. Keep `VITE_API_BASE_URL` empty. Configure preview with a separate database and password. Deployment, production migrations and secret uploads require owner authorization.

```powershell
npm.cmd run deploy:check -- --url https://rahul-portfolio-j94.pages.dev
```

This smoke check uses anonymous GET requests only. It never logs in, writes content, migrates or deploys.

## Verify

```powershell
npm.cmd run typecheck
npm.cmd test
npm.cmd run test:server
npm.cmd run build
npm.cmd run test:production
npm.cmd run test:e2e
npm.cmd run test:e2e:production
```

First-time browser setup: `npx.cmd playwright install chromium`. Browser tests use isolated loopback databases and random test credentials; they refuse production origins. Development tests run on port 5193. The production suite serves built assets and Functions through Wrangler with HTTPS on port 4173. Run browser suites separately.

The owner deferred a known initial keyboard-focus issue in the mobile admin drawer. Its dedicated regression is marked `fixme`; this remains a known accessibility limitation.

`npm run preview` serves the built frontend through Wrangler using local D1. `test:production` checks static build metadata, indexing directives, assets and private-file exclusion; the production Playwright suite verifies runtime behavior.

## Architecture and security

- `src/content/`: shared schemas, cloud repository, API client, explicit legacy migration, backups, images and PDF generation.
- `src/admin/`: authenticated studio, scoped editors, saved draft preview and unsaved-change guards.
- `src/public/`, `src/components/`: existing public routes and safe content rendering.
- `functions/`: Pages entry points; `server/`: authentication, persistence, media, caching and dynamic metadata.
- `migrations/`: additive namespaced D1 schema. Wrangler configs separate local, production and preview bindings.

Secrets stay server-side. Admin APIs require a valid HttpOnly session; every mutation also checks origin and a CSRF token. Login attempts are rate-limited. Shared Zod validation bounds content and URLs, and D1 queries use parameters. Draft content and unpublished images are unavailable anonymously.

Uploaded PNG/JPEG/WebP images are limited to 1 MB and validated dimensions. Referenced images cannot be deleted. JPEG/WebP validation is structural; PNG additionally validates decompressed scanlines. The generated resume supports Western Latin text. The contact form prepares an email-client draft and does not claim server delivery.

Facts and the supplied portrait are documented in `docs/content-source.md`. Missing contact, repository and publication URLs remain empty until supplied. Original private reference PDFs are excluded from deployment. Public design identity remains defined in `DESIGN.md`.

## Git hygiene

`.gitignore` excludes dependencies, builds, local D1/SQLite files, Wrangler state, passwords/secrets, environment values, private references, portable backups, browser traces, screenshots and generated work artifacts. Examples, Wrangler binding files, migrations, application code, tests and the lockfile remain versioned. Ignore rules do not remove tracked files; review staged files before pushing.
